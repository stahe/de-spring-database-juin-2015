    Das Projekt entspricht dem Konfigurationsprojekt [mysql-config-jdbc] der Schicht JDBC des SGBD MySQL (siehe Abschnitt 3.3). Wir stellen hier nur die Änderungen vor:

    • Zeilen 18–22: den Treiber JDBC aus PostgreSQL;

    Die zweite Änderung befindet sich in der Klasse [ConfigJdbc], die die Zugangs-IDs für die Datenbanken definiert:

    
    // Verbindungsparameter
    public final static String DRIVER_CLASSNAME = "org.postgresql.Driver";
    public final static String URL_DBPRODUITS = "jdbc:postgresql:dbproduits";
    public final static String USER_DBPRODUITS = "postgres";
    public final static String PASSWD_DBPRODUITS = "postgres";
    public final static String URL_DBPRODUITSCATEGORIES = "jdbc:postgresql:dbproduitscategories";
    public final static String USER_DBPRODUITSCATEGORIES = "postgres";
public final static String PASSWD_DBPRODUITSCATEGORIES = "postgres";

    Die dritte Änderung, die vorgenommen werden kann, betrifft die maximale Anzahl von Parametern, die ein [PreparedStatement] unterstützen kann:

    
    // Maximale Anzahl von Parametern eines [PreparedStatement]
    public final static int MAX_PREPAREDSTATEMENT_PARAMETERS = 10000;

    Der Test [JUnitTestPushTheLimits] generiert SQL-Aufträge für 5.000 Produkte, die wiederum [PreparedStatement] mit 5.000 Parametern erzeugen. MySQL hatte diesen Wert bereits unterstützt. PostgreSQL ebenfalls.

    Die vierte Änderung ist noch überraschender:

    
public final static String TAB_PRODUITS_ID = "id";
public final static String TAB_CATEGORIES_ID = "id";

    Die Spaltennamen [ID] der Tabellen [CATEGORIES] und [PRODUITS] müssen im Projekt [spring-jdbc-04] in Kleinbuchstaben geschrieben sein. Andernfalls kommt es bei Anweisungen, die die beiden folgenden Beans dieses Projekts verwenden, zu einem Absturz:

    
    // Produkteintrag
    @Bean
    public SimpleJdbcInsert simpleJdbcInsertProduit(DataSource dataSource) {
        return new SimpleJdbcInsert(dataSource)
                .withTableName(ConfigJdbc.TAB_PRODUITS)
                .usingGeneratedKeyColumns(ConfigJdbc.TAB_PRODUITS_ID)
                .usingColumns(ConfigJdbc.TAB_PRODUITS_NOM, ConfigJdbc.TAB_PRODUITS_PRIX, ConfigJdbc.TAB_PRODUITS_DESCRIPTION,
                        ConfigJdbc.TAB_PRODUITS_CATEGORIE_ID);
    }

    // Kategorie einfügen
    @Bean
    public SimpleJdbcInsert simpleJdbcInsertCategorie(DataSource dataSource) {
        return new SimpleJdbcInsert(dataSource).withTableName(ConfigJdbc.TAB_CATEGORIES)
                .usingGeneratedKeyColumns(ConfigJdbc.TAB_CATEGORIES_ID)
                .usingColumns(ConfigJdbc.TAB_CATEGORIES_NOM);
}

    11.3. Konfiguration der Schicht JPA OpenJpa

     

    Das Projekt [postgresql-config-jpa-openjpa] konfiguriert die Schicht [JPA] der Testarchitektur:

    Das Projekt entspricht dem Konfigurationsprojekt [oracle-config-jpa-openjpa] der Schicht JPA OpenJpa von Oracle SGBD (siehe Abschnitt 10.5). Tatsächlich verwenden beide SGBD-Projekte Sequenzen zur Generierung der Primärschlüssel. Es ist lediglich eine Änderung vorzunehmen. Diese befindet sich in der Definition des Beans [jpaVendorAdapter] der Klasse [ConfigJpa]:

    
    // Der Provider JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        OpenJpaVendorAdapter openJpaVendorAdapter = new OpenJpaVendorAdapter();
        openJpaVendorAdapter.setShowSql(false);
        openJpaVendorAdapter.setDatabase(Database.POSTGRESQL);
        openJpaVendorAdapter.setGenerateDdl(true);
        return openJpaVendorAdapter;
}
    • Zeile 6: Der Implementierung JPA wird mitgeteilt, dass sie mit einer Datenbank PostgreSQL arbeiten soll. Die Implementierung JPA übernimmt dann sowohl die proprietären Datentypen als auch die proprietäre SQL dieser SGBD.

    Nach diesen Änderungen sollte die Ausführung der Konfiguration [spring-jpa-generic-JUnitTestDao-openjpa] erfolgreich sein.
