    12.1.2. Erstellung der Datenbanken

    Wie bereits bei Oracle müssen wir den Treiber JDBC von DB2 im lokalen Maven-Repository installieren.

      

    Die Datei [install.bat] enthält den folgenden Code:

    "%M2_HOME%\bin\mvn.bat" install:install-file -Dfile=db2jcc4.jar -Dpackaging=jar -DgroupId=com.ibm.jdbc -DartifactId=db2jcc4 -Dversion=1.0

    wobei [%M2-HOME%] das Maven-Installationsverzeichnis ist (siehe Abschnitt 23.2). Nach dieser Installation kann der Treiber JDBC von DB2 in den Dateien [pom.xml] über die folgende Abhängigkeit referenziert werden:

    
        <dependency>
            <groupId>com.ibm.jdbc</groupId>
            <artifactId>db2jcc4</artifactId>
            <version>1.0</version>
</dependency>

    Im weiteren Verlauf erfolgt die Verbindung zu den Datenbanken DB2 mit den Anmeldedaten [db2admin / db2admin]. Starten Sie DB2 und dessen Client [Db2Manager] (siehe Abschnitt 23.8).

    • Zeilen 18–22: der Treiber JDBC aus DB2;

    Die zweite Änderung befindet sich in der Klasse [ConfigJdbc], die die Zugangs-IDs für die Datenbanken definiert:

    
    // Verbindungsparameter
    public final static String DRIVER_CLASSNAME = "com.ibm.db2.jcc.DB2Driver";
    public final static String URL_DBPRODUITS = "jdbc:db2://localhost:50000/dbprod";
    public final static String USER_DBPRODUITS = "db2admin";
    public final static String PASSWD_DBPRODUITS = "db2admin";
    public final static String URL_DBPRODUITSCATEGORIES = "jdbc:db2://localhost:50000/dbcat";
    public final static String USER_DBPRODUITSCATEGORIES = "db2admin";
    public final static String PASSWD_DBPRODUITSCATEGORIES = "db2admin";

    Die dritte Änderung, die vorgenommen werden kann, betrifft die maximale Anzahl von Parametern, die ein [PreparedStatement] unterstützen kann:

    
    // Maximale Anzahl von Parametern eines [PreparedStatement]
    public final static int MAX_PREPAREDSTATEMENT_PARAMETERS = 10000;

    Der Test [JUnitTestPushTheLimits] generiert Aufträge SQL für 5.000 Produkte, die wiederum [PreparedStatement] mit 5.000 Parametern erzeugen. MySQL hatte diesen Wert bereits unterstützt. DB2 ebenfalls.

    Die vierte Änderung betrifft den Namen der Tabelle [ROLES]. Dieser Name ist nämlich in den Tabellen SGBD und DB2 bereits reserviert. Wir haben sie daher in [ROLES_] umbenannt:

    
public final static String TAB_ROLES = "ROLES_";
public static final String SELECT_ROLES_BYUSERID = "SELECT DISTINCT r.ID as r_ID, r.VERSIONING as r_VERSIONING, r.NAME as r_NAME FROM ROLES_ r, users u, USERS_ROLES ur"
+ " WHERE u.ID=:id AND ur.USER_ID=u.ID AND ur.ROLE_ID=r.ID";

    12.3. Konfiguration der Ebene JPA OpenJpa

     

    Das Projekt [db2-config-jpa-openjpa] konfiguriert die Schicht [JPA] der Testarchitektur:

    Das Projekt entspricht dem Konfigurationsprojekt [mysql-config-jpa-openjpa] der Schicht JPA OpenJpa des SGBD MySQL (siehe Abschnitt 8.3). Tatsächlich verwenden beide SGBD die Annotation [@GeneratedValue(strategy = GenerationType.IDENTITY)] zur Generierung der Primärschlüssel. Es ist nur eine Änderung vorzunehmen. Diese befindet sich in der Definition des Beans [jpaVendorAdapter] der Klasse [ConfigJpa]:

    
    // der Provider JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        OpenJpaVendorAdapter openJpaVendorAdapter = new OpenJpaVendorAdapter();
        openJpaVendorAdapter.setShowSql(false);
        openJpaVendorAdapter.setDatabase(Database.DB2);
        openJpaVendorAdapter.setGenerateDdl(true);
        return openJpaVendorAdapter;
}
    • Zeile 6: Der Implementierung JPA wird mitgeteilt, dass sie mit einer Datenbank DB2 arbeiten wird. Die Implementierung JPA übernimmt dann sowohl die proprietären Datentypen als auch die proprietäre SQL dieser SGBD.

    Nach diesen Änderungen sollte die Ausführung der Konfiguration [spring-jpa-generic-JUnitTestDao-openjpa] erfolgreich sein.
